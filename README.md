# WorkGrid

WorkGrid 是一个用于快速梳理工作内容与工作时间的单人网页工具。

## 0.13.0 更新

日程与长期计划直接显示勾选框，勾选后点击底部“一键删除”，无需进入批量模式。普通日程和计划子日程移入回收站，可撤销或恢复；删除长期计划默认保留子日程，也可在确认时选择一起删除。原有批量颜色、状态、标签和提醒操作保留在“更多操作”中。勾选不会触发编辑或拖动，短日程的移动和调整时长区域继续独立。

## 0.12.2 更新

桌面端显示高度不足 42 像素的短日程恢复时长调整：左半边拖动移动、点击编辑，右半边上下拖动调整时长。两边各占一半，使用点阵和双向箭头区分，聚焦、全天总览和重叠日程同样适用。拉伸过程中保留最初的半区布局，松开不会弹出编辑框。普通日程保留左侧移动把手和右下角拉伸入口；手机保留触摸移动及点击编辑时间。

## 0.12.1 更新

长期计划的待安排列表增加约 260 毫秒的平滑展开/收起动画，快速切换可反向衔接，并尊重“减少动态效果”设置。收起后列表不能交互，展开后的长列表仍限制高度并可滚动。日历日程新增专用移动把手，独立调整时长。移动不改变时长，拉伸不改变开始时间；拉伸取消不保存，松开不弹出编辑框。手机保留触摸拖动和点选排期。

## 0.12.0 更新

新增定量长期计划、先拆分后排期、顶部 DDL 提醒；时间输入可切换开始/结束与开始/时长。课表预览增加搜索、逐节选择、未来周数范围、拖入文件和粘贴文本。更新前建议导出备份；所有设备联网刷新或重开应用，确认更新后再编辑云端数据，避免新旧客户端混用。

## 客户端

WorkGrid 现在是可安装的渐进式 Web 应用（PWA）：

- 支持安装到手机主屏幕或电脑桌面，并以独立窗口运行
- 首次在线打开后可离线启动，日程仍保存在当前设备的浏览器存储中
- 网页版和安装版使用同一套代码，线上版本更新后会自动获取最新资源

- 创建、编辑和删除工作方块

- 待办、进行中、已完成三种任务状态
- 今日进度、计划时长、完成时长与逾期任务处理

- 手机和电脑均可按分钟填写开始、结束时间，或填写开始与时长自动计算结束
- 调整已排工作或移回待安排列表
- 当前视图工作时长统计与时间冲突提示
- 使用浏览器本地存储自动保存数据
- 可选邮箱验证码登录与云同步，登录链接作为备用，支持跨设备实时更新和离线重试
- 首次登录明确选择上传本机数据或使用云端数据，不会静默覆盖
- 导出 JSON 备份、导入预览、合并或覆盖恢复
- 导入前自动创建恢复点，并支持一次性撤销导入
- 内置 ICS 课表导入：课程预览、范围选择、同课同色、重复识别、调课确认和独立撤销
- 为已排期工作设置开始前提醒和预计结束时间提醒
- 为工作添加多个标签，并按标题、标签或状态搜索筛选
- 批量修改工作状态、颜色、标签、开始提醒、结束提醒或删除工作
- 创建、编辑、移动、排期和批量操作后支持快速撤销
- 删除的工作进入回收站，可恢复、永久删除或全部清空
- 桌面端和移动端响应式布局

## 长期计划（0.12.0）

“长期计划 → 新建计划”支持两类：定量计划填写名称、总量（1–500）、单位和每单位预计时长；截止计划填写名称和 DDL，备注及截止提醒可选。DDL 在页面顶部常驻显示，与当前日历日期和筛选独立，完成后隐藏。提醒仅在网页/PWA 运行时检查，不保证关闭应用后的后台通知。

定量计划卡片有“拆分为可安排日程”入口。先选择每个方块包含几节，再生成全部未拆分部分；一节或一组编号只分配一次，重复拆分不会重复生成。展开待安排列表后直接拖入日历或点选时间格，放置时不弹数量框。也可勾选多个未开始方块合并（最多 720 分钟，颜色、标签、提醒须一致）。定量统计由关联日程实时计算，已安排与已完成可以重叠；已完成方块不计入待安排量。修改总量不能小于已拆分的最大编号；修改默认时长/名称/颜色不覆盖现有日程。

截止计划可“添加工作时段”，编辑名称为查资料、初稿等后排期，不改变 DDL。删除关联日程会归还该计划的待安排区并重置完成状态；删除整个计划会保留所有日程、仅解除关联。相关操作可撤销。计划拆分日程不允许生成重复系列，以免重复消耗数量。

开始/结束输入模式自动计算预计时长；开始/时长模式自动显示结束时间。可切换而不改变当前时间段。未安排的方块仍只填写时长；手动填写精确到分钟，支持跨午夜，单个方块保持 1–720 分钟限制。日历拖动仍按已有 15 分钟网格吸附并保留时长，不会反过来修改手动输入值。

计划定义与拆分日程作为同一份数据保存、备份与云同步，不需要新增 Supabase 表/配置。计划记录不会参与日历、工作时长与普通待安排；支持勾选批量删除，但不能与普通日程一起批量修改颜色、状态等字段。备份数据版本为 8，兼容版本 1–7；合并遇到同编号不同版本时，整组计划及其日程复制为新编号，避免串联或重复节次。上线后所有设备需更新再使用：旧客户端无法理解计划字段，不能混用旧版编辑云端数据。

## 日历缩放

周、日和今日视图的日历上方有时间轴工具栏。“− / +”在 25%–150% 间缩放；“全天总览”根据窗口高度显示 00:00–24:00，无需在日历里上下滚动；“默认”恢复原来的显示比例。手机周视图仍可左右滑动查看各天。

缩小后较短日程优先显示标题，点击即可查看完整时间和详情；需要精细排期时可放大。拖动对齐线、15 分钟吸附、点选排期和电脑端时长手柄都使用当前比例，缩放本身不改变任何日程的时间、时长或云端数据。偏好仅保存在本机，刷新后保留。

“聚焦日程”按当前视图及筛选结果，找到最早开始和最晚结束的时间，两端留至少半小时并向整点取整，自动填满日历高度；单个短日程至少保留四小时上下文。周视图各天共用时间轴，日和今日视图只聚焦当天。没有日程时显示全天；跨午夜的日程显示至 24:00，不会改动真实结束时间。

再次点击“聚焦日程”退出，恢复本次进入聚焦前的缩放比例或全天总览；刷新后若仍处于聚焦，退出时恢复默认 100%。

切换聚焦时有 380 毫秒的平滑缩放，尊重系统“减少动态效果”设置。过渡期间日历排期暂不可操作，结束后立即恢复；拖动和时长调整期间保持比例不变，结束后再适配。要安排聚焦范围外的时间，可切回“全天总览”或“默认”；“− / +”切回完整 24 小时的手动缩放。本次不会折叠日程之间的空白，保留连续、等比例的时间轴。

## 提醒说明

WorkGrid 0.9.2 的提醒在应用打开或保持运行时检查。开始提醒可设为开始时或提前 5 分钟至 1 天，结束提醒会在预计时长结束时触发，也可以在批量管理中统一调整。允许浏览器通知权限后会同时显示系统通知；未允许权限时仍会显示应用内提醒。完全关闭网页或应用后的可靠后台提醒，需要后续接入云端推送服务。

## 数据备份

点击页面右上角的“数据管理”图标：

- “导出备份”会下载包含全部工作方块和日程的 JSON 文件，数据不会上传服务器。
- “导入恢复”会先检查文件并展示摘要，可选择合并或覆盖当前数据。
- 每次成功导入前都会保存恢复点，可从同一菜单撤销最近一次导入。

## 课表导入

在教务系统选择“订阅到日历”，复制链接到浏览器下载 `.ics`，然后在 WorkGrid 的“数据管理 → 导入课表”选择文件。无需转换成 JSON，也不需要把个人订阅链接交给 WorkGrid。

默认选择今天及以后的课程，可改为文件中的全部日期。预览显示课程名、起止时间、教室、教师和教学班，可逐门选择和指定七种颜色。上课时间严格按文件保留，时长包含文件所列的课间间隔。

也可以将一个 `.ics` 文件拖入导入窗口，或粘贴完整 ICS 文本后点击“解析文本”；不自动访问订阅链接。内置“试试示例课表”生成从下周起的虚构课程，预览和取消不会保存，确认后才能加入日程，仍可独立撤销。

导入范围增加未来 4、6、14 周，以今天本地时间 00:00 为起点，不含末日边界。预览可以搜索课程名、教室、教师或教学班，逐节勾选新增课程，并对当前搜索结果全选或取消选择。搜索只筛选显示，隐藏的已选课程仍会导入；页面显示实际新增和更新数量。取消的节次在切换范围、课程筛选或颜色后仍保持取消。批量全选不会批准调课或替换手动修改，更新仍需逐节确认。

导入不会移动、删除或覆盖普通日程，时间重叠仅提示。同来源、同课程编号再次导入不会新增副本，下载时间变化不会影响去重。课表有变化时需逐节勾选确认，手动修改过的课更会明确提示；颜色、标签、状态和提醒设置保留。课表中消失的旧课程不会自动删除，已移入回收站的课程不会自动恢复。

“撤销上次课表导入”只处理这一次新增或更新的课程，保留原有日程及后续修改。导入后又修改的课程会跳过撤销；恢复记录保存在导入设备上。课表来源和教室等信息会随 JSON 备份及账户云同步保留。当前备份数据版本为 8，版本 1–7 的旧备份仍可导入；旧客户端无法识别新字段，跨设备使用前需更新应用。

文件在本机解析；确认导入后，已登录账户沿用已有日程云同步。当前支持最大 2MB、5000 节课程。使用 `ical.js` 处理折行、文本转义、UTC/浮动时间、课表时区、按日/周/月/年重复、排除日期和调课覆盖；重复课程展开至导入当天的一年后，过于复杂的规则拒绝导入。全天事件会明确提示并跳过，缺少时区定义（北京时间除外）或无效起止时间会阻止导入，避免猜测时间。

本功能导入的是下载当时的课表快照，不会保存订阅 token 或自动访问学校链接。学校调课后需重新下载导入；有些学校的编号可能随调课变化，应在预览中核对，不能仅凭课程名称自动替换。

## 云同步

WorkGrid 0.9.2 使用 Supabase 提供可选云同步。未登录时仍是完整的本机应用；用户可直接在当前页面输入邮箱中的 6 至 8 位验证码登录，邮件登录链接保留为备用。登录后，本机每次修改会自动同步，同一账户的其他设备会收到更新，包括回收站中的工作。断网时修改继续保存在浏览器，恢复网络后自动重试。多台设备同时修改时，应用会暂停同步并要求用户明确选择本机或云端版本，避免静默覆盖；账户面板也会显示待上传状态、失败原因，并允许删除云端数据而保留本机日程。

云端表启用了行级权限，每位用户只能读取和修改自己的数据。导出备份仍然保留，建议定期下载独立备份。

部署前需要：

1. 在 Supabase 创建项目，在 SQL Editor 执行 `supabase/migrations/20261005000000_create_workgrid_data.sql`。
2. 在 Authentication 的 URL Configuration 中，把 `https://zhoubx634.github.io/workgrid/` 加入 Redirect URLs。
3. 在 Authentication 的 Email Templates 中同时修改 Confirm signup 和 Magic Link 模板，两者都加入 `{{ .Token }}` 验证码和 `{{ .ConfirmationURL }}` 登录链接，示例见 [Supabase 配置说明](supabase/README.md)。
4. 在 GitHub 仓库的 Actions secrets 中添加 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY`。
5. 重新运行 GitHub Pages 工作流。Supabase 的 anon key 是网页客户端可用的公开密钥，安全隔离由数据库行级权限负责；不要使用 service role key。

本地开发可将 [.env.example](.env.example) 复制为 `.env.local` 并填写同样的两项配置。未配置时云同步入口自动隐藏，其他功能不受影响。

## 本地运行

```bash
npm install
npm run dev
```

打开终端显示的本地地址即可使用。

## 正式构建

```bash
npm run build
```

构建结果位于 `dist` 目录，可部署到任意静态网站托管服务。

```bash
npm test

npm run test:ui
```
